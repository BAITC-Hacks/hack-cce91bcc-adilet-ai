# Локальное демо MoneyGraph

## Интерфейс мониторинга

Оболочка использует тёмно-синюю навигацию, светлый фон, белые карточки и
бирюзовые акценты. `dashboard/frontend/` содержит CSS и JavaScript,
`dashboard/ui.py` — подключение представления к Streamlit Components v2.
Сборка npm и внешние CDN не нужны. Для запуска установите существующие
`requirements.txt` и `dashboard/requirements.txt`.

На обзоре показаны четыре показателя из исходной выборки и таблица
приоритетных узлов. JavaScript выполняет поиск по строковому gid, фильтрацию
по роли, числовую сортировку по входящей сумме/приоритету и пагинацию.
Кнопка «Открыть» передаёт только gid в существующий экран узла. Таблица
не получает пароли, резервные коды или токены; данные вставляются через
`textContent`, без интерпретации пользовательского HTML. Для выгрузки всего
top_nodes предусмотрен раздел «Исходная таблица и экспорт CSV».

Период интерфейса — июль 2026, как в исходной выборке. Приоритет не называется
вероятностью риска. Когда файлы отсутствуют, карточки показывают «—», таблица
остаётся пустой, а раздел «Источник данных» позволяет задать пути. Данные
примера автоматически не подставляются. На узких экранах карточки
переносятся в одну колонку, таблица прокручивается горизонтально.

Проверки без приватного датасета:

```bash
python -m pytest tests/ui/test_accounts.py tests/ui/test_storage.py tests/ui/test_shell.py tests/ui/test_app.py::test_forged_session_has_no_access tests/ui/test_investigation.py tests/ui/test_provenance.py -q
```

Аутентификация, SQLite и расчётный pipeline при обновлении UI не менялись.

## Регистрация и вход по email и паролю

Google/OIDC не используется. На первом экране выберите «Регистрация»,
введите имя, email и пароль длиной 15–128 символов. Сохраните показанный
резервный код и перейдите ко входу. Новые зависимости и внешние ключи не нужны.
Email служит логином; отправка писем и подтверждение владения адресом не подключены.
Регистрация открыта для пользователей локального экземпляра приложения.

Каждый аккаунт видит свои заметки, проверки и историю. Исходный граф общий
для всех зарегистрированных аналитиков. Старый общий профиль и его заметки
сохраняются в БД, но автоматически новым аккаунтам не передаются.

В боковой панели доступны «Выйти», смена пароля и выход на всех устройствах.
Смена пароля завершает все сессии и требует повторного входа.
«Восстановление» принимает email, резервный код и новый пароль; прежний код
становится недействительным, новый показывается один раз. Почтовый сервис
не требуется. При потере и пароля, и кода автоматического восстановления нет.

### Хранение паролей и сессий

Пароли хранятся как PBKDF2-HMAC-SHA256 с 600 000 итераций и случайной солью
16 байт. Сравнение хешей использует constant-time операцию. В SQLite нет
исходных паролей, резервных кодов или исходных токенов сессий.
Сессия определяется случайным токеном 256 бит; в БД хранится его SHA-256.
Токен остаётся только в серверной сессии Streamlit, не помещается в URL или
localStorage. Каждый повторный запуск страницы проверяет сессию в БД.
Срок — 8 часов с момента входа или 30 минут без действий. После полной
перезагрузки вкладки/перезапуска сервера нужен новый вход; заметки остаются.

После 5 неверных попыток входа за 15 минут аккаунт временно блокируется.
Для восстановления и смены пароля действуют отдельные такие же ограничения.
Проверки сохраняются в БД и не сбрасываются обновлением страницы.
Лимит привязан к email, не заменяет защиту публичного сервиса на уровне сети.
XSRF и CORS включены. Локальный запуск привязан к localhost; для публикации
потребуются HTTPS, политика регистрации и почтовый сервис, если нужно подтверждение email.

Рекомендации по хранению паролей и сессиям:
[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html),
[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

SQLite создаётся автоматически при запуске. Тема в
`dashboard/.streamlit/config.toml` использует зелёную палитру и светлые карточки.

### Что сохраняется

SQLite по умолчанию: `data/moneygraph.sqlite3`, путь можно изменить переменной
`MONEYGRAPH_DB`. Дополнительный сервер БД не нужен. В базе:

- `users`: аккаунты и профили; прежние локальные/OIDC-профили остаются в базе;
- `credentials`: хеши паролей и одноразовых резервных кодов;
- `sessions`: хеши токенов, сроки и активность сессий;
- `auth_limits`: ограничения попыток входа, восстановления и смены пароля;
- `datasets`, `assets`: версии трёх parquet и трёх CSV, точные байты и SHA-256;
- `cases`: заметки профиля, статус проверки, gid строкой, версия данных и записка;
- `events`: регистрация, вход/выход, смена/восстановление пароля, открытие узла и каждое сохранение проверки (история показывает последние 100).

Исходный расчёт продолжает читать parquet и выпускать обязательные CSV. SQLite
хранит архив этих файлов и работу аналитика; она не заменяет контракт pipeline.
Снимок сохраняется при открытии набора и повторно не дублируется, если байты совпадают.
Заметки и статус записываются по кнопке «Сохранить в мои проверки», не при каждом нажатии клавиши.
Фильтры графа не сохраняются между сессиями. База не публикуется в Git.
Для резервной копии остановите приложение и скопируйте SQLite-файл.
Запуск рассчитан на один локальный сервер; для нескольких реплик потребуется общая БД.

### Сценарий работы

После входа выберите приоритетный узел на обзоре → «Исследовать узел» →
изучите наблюдения и предшественников → добавьте заметку и статус → сохраните.
В «Мои проверки» доступны сохранённые записки и переход к редактированию.
Проверка старой версии данных остаётся доступна как архивная записка.

### Про AI-агента

Текущая версия — аналитический pipeline и рабочее пространство, не LLM-агент.
В предоставленных starter/README и README датасета нет требования автономного
агента или обязательного OpenAI API. Если полное ТЗ требует агента, его нужно
сверить отдельно. Возможное расширение: помощник принимает вопрос, вызывает
инструменты поиска узла/предшественников/объяснения и готовит записку с фактами.
Детерминированный поиск и шаблон записки не выдаются за AI-агента.

## Запуск

UI читает реальные результаты CORE и не присваивает роли. Данные не
отправляются во внешний API. Запуск из корня проекта:

```bash
source .venv/bin/activate
python -m pip install -r dashboard/requirements.txt
python run.py --data ./data --out ./out
python -m streamlit run dashboard/app.py -- --data ./data --out ./out
```

Откройте адрес, напечатанный Streamlit (обычно http://localhost:8501).
Пути можно менять в боковой панели; относительные пути всегда считаются
от корня проекта, даже при запуске из другого каталога. Чтение CSV и layout
кешируются. Кеш CSV обновляется при изменении размера или mtime входного
файла. При отсутствующих/пустых/невалидных файлах отображается ошибка и
команда запуска pipeline, без подстановки синтетических клиентов.

## Сценарий на 2–3 минуты

1. **Обзор:** количество узлов, направленных пар и переводов вычисляется
   из файлов. В текущих данных это 2248, 3119 и 4840. Покажите таблицу
   приоритетов и сортировку по столбцам. Скопируйте полный gid первой строки.
2. **Узел и переводы:** вставьте gid. Объясните отдельно роль-гипотезу,
   силу правила и приоритет проверки. Прочитайте числовое evidence,
   наблюдаемые вход/выход и число контрагентов. Эти scores не являются
   вероятностью правонарушения или измеренной точностью классификации.
3. Покажите направленный граф одного шага: стрелки идут от плательщика
   к получателю. Сумма и число переводов отображаются при наведении на
   середину ребра и в таблице. Взаимные направления немного разнесены.
   Ограничьте соседей, выберите входящие/исходящие, задайте минимум суммы.
   Граф ограничен 60 соседями (до 120 пар), выбираемыми по наблюдаемой
   сумме; layout с seed=42. Все переводы выбранного узла доступны ниже
   в отдельной таблице без фильтра графа. Это не полный граф кластера.
4. **Кластеры:** откройте номер из карточки узла. Сопоставьте размер,
   seed, внутренний оборот и top_gids с гипотезой. Объясните, что
   кластеризация выполнена CORE на ненаправленной проекции.
5. Для ограничений выберите seed, изолированный seed и узел depth=4.
   В карточках есть явные предупреждения о неполных входящих, техническом
   pass_through=0 без входа и неизвестных дальнейших переводах на границе.
   fast2 показывает возможное сопоставление за 0–2 дня: время суток
   отсутствует, порядок и путь конкретной суммы не доказаны.

Полные gid хранятся строками при загрузке CSV и передаче в UI/Plotly:
18-значные идентификаторы не округляются JavaScript. Живое приложение
использует только исходные edges.parquet и три настоящих CSV.

# Демонстрация Freedom Flow

Полная установка, контракт CSV и описание метода — в [README](../README.md).
Обычный запуск из корня проекта:

```bash
python -m streamlit run dashboard/app.py -- --data ./data --out ./out
```

## Что показать жюри

1. **Стартовая страница:** название и логотип Freedom Flow из `main`, задача продукта, цепь как иллюстрация связей, кнопки
   входа и регистрации, используемые технологии внизу.
   Справа сверху переключите RU / EN / KZ; язык сохраняется в адресе страницы.
2. **Вход:** оформление Freedom Flow из `main` с формой справа; создайте аккаунт, сохраните резервный код (есть скачивание), войдите.
   После входа нажмите значок аккаунта справа сверху: имя, email, выход и смена пароля.
   Пароль — 15–128 символов. Email служит логином, почтовая отправка не подключена.
3. **Обзор:** проверьте 2 248 участников, 3 119 связей, 4 840 переводов и 91 группу.
   Следуйте подсказкам «Выберите участника → Исследуйте связи → Сохраните проверку».
   В таблице работают поиск по ID, фильтр роли, сортировка сумм/приоритета и страницы.
4. **Узел и переводы:** откройте участника, сопоставьте роль и числовые наблюдения.
   Проверьте предшественников до четырёх шагов и направленные связи одного шага.
   Крупный узел на графе — выбранный участник, стрелка направлена к получателю.
   Наведение показывает суммы и роли. Лимит соседей и минимальную сумму можно менять.
5. **Границы данных:** откройте исходного участника (seed), изолированного seed и
   узел на четвёртом шаге. Проверьте предупреждения. Путь не доказывает движение
   одной суммы; дата без времени суток не устанавливает порядок переводов.
6. **Мои проверки:** сохраните заметку и статус, найдите их по тексту или ID,
   отфильтруйте по статусу, скачайте записку. После выхода и входа заметка остаётся.
   Другой аккаунт не видит её. Архивные записки доступны даже без исходных файлов.
7. **Кластеры:** выберите группу, изучите гипотезу и перейдите к её участнику.
8. **AI-расследователь:** откройте AI-проверку из строки приоритетной таблицы,
   участника кластера или сохранённой проверки. Можно выбрать любого из 2 248 участников.
   В режиме очереди дайте согласие и нажмите «Расследовать следующую цепочку».
   Каждое нажатие проверяет окружение одного участника. Ошибка оставляет его
   следующим кандидатом; успешная проверка продвигает очередь.
9. **Проверяемость:** скачайте три обязательных CSV. Для файлов проверяется
   паспорт запуска, для MariaDB — манифест и содержимое выбранного снимка.

Роль — гипотеза, сила правила — выраженность признаков, приоритет — очередь
ручной проверки. Ни один из этих показателей не является вероятностью нарушения.

## Источник аналитики и хранение работы

При настроенных `MYSQL_*` в `.env`/окружении приложение использует готовую
MariaDB для аналитики, аккаунтов, сессий, заметок, истории и AI-кеша.
Аналитика находится в `mg_*`, рабочее пространство — в `mg_workspace_*`.
Нужен установленный CLI-клиент `mariadb`. Сервер автоматически не устанавливается.
Настройки читаются без исполнения `.env`; секреты не выводятся в интерфейс.

В боковой панели «Источник данных» можно явно выбрать MariaDB или файлы.
В режиме MariaDB выберите опубликованный снимок. Шесть таблиц читаются одной
согласованной транзакцией только для чтения; проверяются схема, число строк,
контрольные суммы, суммы и количество переводов. Parquet/CSV на диске для чтения
такого снимка не нужны. «Обновить данные» обновляет кеш и список версий.
Время и диагностика локального pipeline не входят в снимок MariaDB.

Аккаунты и аналитика — независимые настройки: выбор файлов в боковой панели
не переносит аккаунт из MariaDB. Для полностью локального режима:

```bash
MONEYGRAPH_DB=./data/moneygraph.sqlite3 MONEYGRAPH_DATA_SOURCE=files \
  python -m streamlit run dashboard/app.py
```

Перенос существующих аккаунтов и заметок из SQLite:

```bash
python -m dashboard.maria_storage --migrate-sqlite ./data/moneygraph.sqlite3
```

Перенос атомарный и повторяемый, исходный файл не меняется. Хеши паролей,
резервных кодов и сессий сохраняются. Конфликт аккаунтов останавливает перенос,
чтобы не присоединить чужую заметку. Старый общий профиль не становится новым
персональным аккаунтом. База и данные не публикуются в Git.

Записка связана с точной версией шести файлов. MariaDB восстанавливает parquet
с другим бинарным представлением; при переключении источника прежняя записка
может отображаться архивной, даже если наблюдаемые строки совпадают.

## Вход и удобства

Формы расположены по центру, на мобильном экране занимают доступную ширину.
«На главную» возвращает обложку. Email и имя сохраняются при ошибках формы.
Поля поддерживают менеджер паролей; пароль можно показать штатной кнопкой поля.
Резервный код виден только после регистрации/восстановления, его можно скачать.

Пароли хранятся как PBKDF2-HMAC-SHA256 с 600 000 итераций и случайной солью.
На сервере хранятся только хеши случайных токенов и резервных кодов.
Обычная сессия действует до восьми часов и завершается после 30 минут бездействия.
«Запомнить меня на 30 дней» сохраняет отзывной токен в localStorage текущего
браузера и origin; пароль туда не записывается. Токен доступен JavaScript этого
origin, поэтому запоминание предназначено для личного устройства.
При запрете browser storage текущая сессия продолжает работать.

Выход отзывает текущую сессию. Смена/восстановление пароля и «Выйти на всех
устройствах» отзывают все сессии. Резервный код одноразовый. После пяти неверных
попыток за 15 минут применяется ограничение по email. Почтовое восстановление
не подключено: при потере пароля и кода автоматического восстановления нет.

## Как проверяли

```bash
python -m pytest tests/core tests/ui -q
python bench/verify.py
```

Проверки покрывают неверные ID и пароли, истечение/отзыв токенов, изоляцию
пользователей, сохранение/редактирование, отсутствие файлов, сбои хранилища,
сохранение текста при ошибке записи, повреждённые снимки и ограничения графа.
Тесты внешнего AI используют mock-провайдер и не тратят API-токены.
Live-тесты MariaDB включаются отдельно, используют временный префикс таблиц
и удаляют только созданные ими таблицы:

```bash
MONEYGRAPH_TEST_MARIADB=1 python -m pytest tests/ui/test_maria_storage.py -q
```

Для браузерной проверки нужны Playwright и Chromium как инструменты разработки:

```bash
python -m pip install playwright
python -m playwright install chromium
MONEYGRAPH_DB=/tmp/moneygraph-browser.sqlite3 MONEYGRAPH_DATA_SOURCE=files \
  python -m streamlit run dashboard/app.py --server.port 8510
# В другом терминале:
python tests/ui/browser_smoke.py --url http://127.0.0.1:8510 --out /tmp/moneygraph-ui
```

Браузерный сценарий создаёт тестовый аккаунт. Запускайте его на отдельном
тестовом рабочем пространстве, как в команде выше. Проверяет регистрацию,
ошибки формы, вход, запоминание после полной перезагрузки, заметку, неизвестный
ID, выход и отсутствие горизонтального переполнения на экране 390 px.
Скриншоты сохраняются в указанном временном каталоге. AppTest сам по себе
не проверяет CSS или браузерный JavaScript.

## AI по желанию

В карточке участника AI запускается только по кнопке и после согласия отправить
ограниченный фрагмент кейса. Настройки и границы — в README. Граф и обязательные
CSV работают без AI. Гипотеза модели сверяется с вычисленными фактами; ошибка
провайдера не скрывает базовую аналитику. Локальное исключение узла работает без API.

Оркестрация — настоящий `langgraph==1.2.12`: `StateGraph` с узлами
`plan → check → conclude`, условным повтором проверок и конечным лимитом шагов.
[Документация StateGraph](https://reference.langchain.com/python/langgraph/graph/state/StateGraph).
Сначала локально собирается профиль и проверяется кеш. Модель составляет план
с поддерживающими и опровергающими проверками; инструменты исполняются локально,
а итог проходит проверку структуры и точных ссылок на реестр фактов.
Обычно выполняются два запроса модели; на исправление структуры разрешена одна
дополнительная попытка на весь запуск. Ограничения времени, числа инструментов,
размера контекста и сетевых повторов сохранены. Внешняя трассировка LangSmith
отключена для этого графа; checkpoints во внешние сервисы не отправляются.

Планировщика и фоновых расследований нет. Переход по кнопке «Проверить через AI»
только открывает выбранного участника. После согласия нужно отдельно нажать
кнопку расследования. Перезагрузка страницы, выбор языка, фильтры и навигация
не вызывают API. Очередь идёт по `priority_score` с разрешением равенств по `gid`;
она хранится только в текущей сессии отдельно для пользователя, снимка и языка.
«Цепочка» здесь означает ограниченное окружение участника, а не доказанный путь
конкретных денег; соседние кейсы могут пересекаться. Кеш проверенных результатов
хранится в выбранной базе, разделён по пользователям, данным, модели и языку.
Повторный успешный запрос из кеша не расходует API-токены.

Интерфейс и запрос свободного текста модели используют выбранный язык.
Числовые факты, идентификаторы и служебные значения JSON не переводятся.
Заметки пользователей, исходные гипотезы CSV и исходные экспорты сохраняют язык
источника. Каталог интерфейса: `dashboard/locales.tsv` (RU, EN, KK; кнопка KZ).
Автоперевод через внешний сервис не используется. Тесты проверяют полноту
каталога для статических вызовов `t` и сохранение всех параметров шаблонов.

Обновление зависимостей и проверка:

```bash
python -m pip install -r requirements.txt -r dashboard/requirements.txt
python -m pytest tests/ui tests/core -q
python -m streamlit run dashboard/app.py -- --data ./data --out ./out
```

Для браузерного теста нужен отдельный `MONEYGRAPH_DB` в `/tmp`, Chromium/Playwright
и `AI_ENABLED=false`. Сценарий `tests/ui/browser_smoke.py` проверяет смену RU/EN/KZ,
сохранение языка после перезагрузки, подписи таблицы, AI-переходы и меню аккаунта,
а также регистрацию, сохранение заметки, выход и экраны 1440/390 px.
Проверки LangGraph и очереди используют mock-провайдер, реальные платные запросы
не запускаются. Качество выводов реальной модели ими не оценивается.

  не вызывался; работоспособность платного провайдера и качество его текстов
  требуют отдельной ручной проверки с настроенным ключом.

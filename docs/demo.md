# Локальное демо MoneyGraph

UI читает реальные результаты CORE и не присваивает роли. Данные не
отправляются во внешний API. Запуск из корня проекта:

```bash
source .venv/bin/activate
python -m pip install -r dashboard/requirements.txt
python run.py --data ./data --out ./out
python -m streamlit run dashboard/app.py -- --data ./data --out ./out
```

Откройте адрес, напечатанный Streamlit (обычно http://localhost:8501).
Пути можно менять в боковой панели; относительные пути всегда считаются
от корня проекта, даже при запуске из другого каталога. Чтение CSV и layout
кешируются. Кеш CSV обновляется при изменении размера или mtime входного
файла. При отсутствующих/пустых/невалидных файлах отображается ошибка и
команда запуска pipeline, без подстановки синтетических клиентов.

## Сценарий на 2–3 минуты

1. **Обзор:** количество узлов, направленных пар и переводов вычисляется
   из файлов. В текущих данных это 2248, 3119 и 4840. Покажите таблицу
   приоритетов и сортировку по столбцам. Скопируйте полный gid первой строки.
2. **Узел и переводы:** вставьте gid. Объясните отдельно роль-гипотезу,
   силу правила и приоритет проверки. Прочитайте числовое evidence,
   наблюдаемые вход/выход и число контрагентов. Эти scores не являются
   вероятностью правонарушения или измеренной точностью классификации.
3. Покажите направленный граф одного шага: стрелки идут от плательщика
   к получателю. Сумма и число переводов отображаются при наведении на
   середину ребра и в таблице. Взаимные направления немного разнесены.
   Ограничьте соседей, выберите входящие/исходящие, задайте минимум суммы.
   Граф ограничен 60 соседями (до 120 пар), выбираемыми по наблюдаемой
   сумме; layout с seed=42. Все переводы выбранного узла доступны ниже
   в отдельной таблице без фильтра графа. Это не полный граф кластера.
4. **Кластеры:** откройте номер из карточки узла. Сопоставьте размер,
   seed, внутренний оборот и top_gids с гипотезой. Объясните, что
   кластеризация выполнена CORE на ненаправленной проекции.
5. Для ограничений выберите seed, изолированный seed и узел depth=4.
   В карточках есть явные предупреждения о неполных входящих, техническом
   pass_through=0 без входа и неизвестных дальнейших переводах на границе.
   fast2 показывает возможное сопоставление за 0–2 дня: время суток
   отсутствует, порядок и путь конкретной суммы не доказаны.

Полные gid хранятся строками при загрузке CSV и передаче в UI/Plotly:
18-значные идентификаторы не округляются JavaScript. Живое приложение
использует только исходные edges.parquet и три настоящих CSV.

## Проверки и статус

```bash
python -m pytest tests/ui -q
python -m pytest tests/core tests/ui -q
```

Проверены реальные файлы: nodes_roles.csv — 2248 строк, clusters.csv — 91,
top_nodes.csv — 20. Проверки UI загрузки сверяют обязательные поля,
уникальность и точность gid, роли, конечность и диапазон score, соответствие
top_nodes, порядок/rank, состав/размеры кластеров и внутренние суммы,
направленные пары и их концы. Тесты проверяют пустые/отсутствующие файлы,
некорректные score, дубликаты, несовпадение top, округлённый gid, отсутствие
колонки, UTF-8, изолированный seed, depth=4, ограничения и детерминизм графа.

В текущем окружении: **10 UI-тестов прошли за 2.61 с; 1 модуль AppTest
пропущен**, потому что Streamlit и Plotly отсутствуют. Их скачивание требует
доступа к сети; запрос установки был отклонён. Поэтому фактический запуск
Streamlit и визуальная проверка браузером пока не подтверждены. После
установки dashboard/requirements.txt AppTest проверит реальный обзор,
карточку, неизвестный gid, изолированный/depth=4 узлы, одиночный и большой
кластер и ошибку недоступного пути. Версии UI заданы совместимыми диапазонами;
фиксировать проверенные версии следует после успешной установки.

Время CORE по последней документированной проверке: 3.54 с первый запуск,
2.78 с повторный. UI не добавляет алгоритмов CORE или нативных зависимостей.
Ветка/коммит не создавались; данные и результаты не публиковались.

# MoneyGraph — общие правила для двух Codex

## Цель и источник требований

Кейс HackAlem AI «Граф денег». Работайте с приложенными `starter/starter.py`,
`starter/README.md`, `docs/dataset_README.md` и локальными parquet. Если появится полное официальное
ТЗ трека, сверьте его и обновите контракт до изменения кода. Старый план
HackalemAI про AI-юриста к этому проекту не относится.

Выпуск: воспроизводимый pipeline → `out/nodes_roles.csv`, `out/clusters.csv`,
`out/top_nodes.csv`; затем демонстрационный Streamlit UI на этих файлах.
Поддерживайте запуск `python run.py --data ./data --out ./out`.

## Порядок работы и skills

1. Сначала прочитайте этот файл, оба README и схему/каркас `starter.py`.
   Сравните требования с фактическими колонками и данными.
2. В первом коротком сообщении назовите свой участок, этапы, ожидаемые файлы,
   проверку результата и только применимые доступные skills (название + для
   чего). Если полезных skills нет, скажите это одним предложением. Не читайте
   и не перечисляйте все навыки ради отчёта, не создавайте новый skill без
   практической потребности. Правила локальных AGENTS и skills учитывайте.
3. Работайте самостоятельно короткими проверяемыми шагами. После каждого
   этапа сообщайте измеримые результаты, найденные ограничения и следующие
   действия. Не заменяйте выполнение подробным планом.
4. Перед сдачей сообщите команды запуска, число строк каждого CSV, время
   pipeline, пройденные проверки и невыполненные требования. Обоснуйте любую
   нативную зависимость измерением, а не предположением.

## Обязательный контракт

- `nodes_roles.csv`: по одному уникальному `gid` на все 2248 узлов;
  обязательные колонки: `gid, role, role_score, cluster_id, priority_score,
  evidence, in_deg, out_deg, in_kzt, out_kzt, pagerank, pass_through, depth,
  is_seed, truncated_by_depth`. `role` — ровно одна из `consolidator`,
  `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`.
  `role_score` и `priority_score` конечны и в диапазоне [0,1]. `evidence`
  непустое, с наблюдаемыми числами, длина <=200 символов.
- `clusters.csv`: `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids,
  hypothesis`. Каждая вершина входит ровно в один кластер; сумма `n_nodes`
  равна 2248, включая изолированные seed. Гипотеза содержит наблюдения,
  описывает ограничение данных и не объявляет мошенничество доказанным.
- `top_nodes.csv`: `rank, gid, role, priority_score, why`; >=20 различных
  существующих `gid`, сортировка по убыванию score, при равенстве по `gid`,
  rank подряд от 1. `why` основано на числах из анализируемых данных.
- Сохраняйте `gid` как целое/строку, никогда как float; не допускайте
  пропуска, inf, строк `nan` в обязательных значениях. Для не определённого
  `pass_through` в CSV задайте явно описанное конечное значение и ведите
  отдельный флаг отсутствующего входящего в расчётах; ноль не значит
  «отсутствия транзита» для seed.

## Ограничения выборки и проверка

- Это наблюдаемые исходящие переводы, начиная с 81 seed, до 4 колен, за июль
  2026. 19 seed изолированы; перед сетевыми метриками добавьте ВСЕ 2248 `gid`
  в граф. 444 узла на `depth=4` не имеют наблюдаемых исходящих: нельзя
  автоматически объявлять их `terminal`. Входящие seed неполные; их
  `pass_through` и баланс нельзя трактовать как полноценный поток.
- В `transactions.parquet` только дата, без времени суток: совпадение дня
  показывает возможную последовательность, не доказанный порядок или путь
  конкретных денег. Все суммы относятся только к наблюдаемому графу.
- Сверьте пары `src,dst`, `sum_kzt` с допуском 0.01 KZT, `n_tx`, уникальность
  `gid`, наличие всех концов рёбер, даты и неотрицательные значения. Затем
  проверьте экспорт, детерминированность повторного запуска и 3–5 разобранных
  `gid` (seed, изолированный, depth=4, транзитный кандидат, узел с большим
  входом/выходом). Роль — аналитическая гипотеза, `role_score` — сила правила,
  не калиброванная вероятность; `priority_score` — приоритет проверки, не
  оценка вероятности правонарушения.

## Скорость и C++

Измеряйте время стадий. На ~2248 вершинах и ~3119 рёбрах сначала используйте
векторизованные pandas/NumPy и направленные NetworkX-алгоритмы с ограничением
объёма вычислений. Не запускайте без лимита перечисление всех простых путей
или циклов. Для приближённого betweenness зафиксируйте `k`, seed и то, что
вес кратчайшего пути означает расстояние, а не объём перевода.

Переходите на существующую нативную библиотеку или модуль C++/pybind11 лишь
если замер показал узкое место (например, полный pipeline >15 с либо стадия
занимает >40% времени), паритет с Python на контрольных случаях проверен и
общее время запуска с учётом сборки/импорта улучшилось. Нативный код должен
иметь чистый Python fallback и простой способ сборки на целевой ОС. Если
ускорение не нужно, прямо сообщите замер вместо добавления C++ ради C++.

## Внешний AI и секреты

Официальная публичная страница HackAlem требует использовать Codex при
разработке; из доступных материалов этого кейса требование именно OpenAI API
не подтверждено. Никакой внешний вызов не должен быть условием расчёта трёх
CSV. При появлении отдельного требования трека добавляйте только опциональное
объяснение, основанное на уже вычисленных фактах, с ключом из переменной
окружения, без передачи исходного датасета целиком. Запрещены выдуманные
транзакции, даты, связи и «доказательства мошенничества».
